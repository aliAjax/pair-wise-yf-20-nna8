# hxyfront-62008 烟花燃放脚本 · 双端离线合并台

面向烟花燃放排练：主控平板与备份平板离线各改一份脚本，联网后按点火节点逐字段合并，
不再出现「后保存的把先改的点位/时间盖掉」。

预置 **三段节目、四个点位、八枚烟花**。

## 合并规则

- 每台平板记录：节目段落、点火节点、**点位、点火时刻、安全距离、音乐时间点**；
  每次修改留痕 **设备号（M 主控 / B 备份）+ 本机单调序号**。
- 联网后按节点合并四字段（点位 / 时刻 / 安全距离 / 型号）：
  - 只有一端改、或两端改成相同值 → **自动写入**；
  - 同一字段两端改成不同值 → **保留两版待选择**，人工裁定后才生效。
- **有未处理冲突（或未确认的回退阻塞）的段落不能发布**，门禁逐段落判定。
- 安全距离变化会联动：
  1. 按距离自动重选覆盖型号；
  2. 重算点位危险区（型号要求半径 vs 安全距离取大）；
  3. 汇总各点位型号用量与容量。
- 所选版本触发 **容量冲突 / 危险区超场地 / 点火时刻越出音乐锚点（±容差）** 时，
  **保留最后一次通过的版本**，并在合并台显示**最早阻塞节点**（按点火顺序 N1→N8）。
- 合并可中途断网：本地改动与会话状态不丢；恢复后点「重试 / 继续合入」，
  已写字段带幂等键（opId），**不会重复写入**。
- 全部落定后可把通过版本同步回两台平板，进入下一轮离线改稿。

## 页面分区

1. **离线改稿台**：切换主控/备份，编辑八枚烟花的点位、时刻、安全距离（型号随距离自动选型）。
2. **联网合并台**：开始合并、单步/批量泵入（可随时模拟断网）、冲突两版选一、阻塞确认；
   红条显示最早阻塞节点。
3. **发布门禁**：三段节目的可发布状态与阻塞原因。
4. **点位平面图 + 型号用量**：危险区圆、场地区间、各点位容量用量实时重算。
5. **操作流水**：所有写入/裁定/回退/发布的幂等日志。

点「① 载入排练现场」可一键还原一个典型场景：
主控 N4 改时刻越出锚点、N5 改 70m 超一号台场地；备份 N1 自动合入、N5 改 50m 与主控冲突、
N7 改 55m 撑爆三号台容量；主控 N6 自动合入。

## 代码结构

| 文件 | 内容 |
| --- | --- |
| `src/types.ts` | 领域类型（节点/段落/点位/型号/副本/会话/阻塞/视图） |
| `src/preset.ts` | 三段节目、四个点位、五种型号、八枚烟花的预置数据 |
| `src/engine.ts` | 纯函数合并引擎：差异识别、自动合入、冲突裁定、锚点/危险区/容量评估、回退、门禁、幂等流水 |
| `src/App.tsx` + `src/styles.css` | 排练控制台 UI |
| `test/engine.test.ts` | 12 个 Node 内置测试：留痕、自动合入、冲突、回退、门禁、中断重试幂等等 |

合并引擎不依赖 React/DOM，全部为「传入旧 World、返回新 World」的纯函数，可独立单测与复算。

## 本地运行

```bash
npm install
npm run dev       # 开发，端口 62008
npm test          # 引擎单测（node:test，无需额外框架）
npm run build     # tsc 类型检查 + vite 构建
```
